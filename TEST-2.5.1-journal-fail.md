## Подтверждённые отказы PT-CC-19 / PT-CC-25

В create-claster.sh функция restore_target_conflict (около строки 1257) ищет совпадение только по имени: `$2 == n`, без ограничения целевой major. Её используют cold restore и rename.

Модель реестра: `18 occupied`; целевая пара `17/occupied`, отдельный путь /fixture/17/occupied. Ожидается отсутствие конфликта (внутренний rc=1); фактически функция возвращает конфликт (rc=0):

> имя кластера occupied уже зарегистрировано (PostgreSQL 18); выберите другое имя независимо от версии

Одинаковый результат получен с обычной политикой и policy=rename на 8/8 WSL. **rc=0 здесь означает найденный конфликт внутренней функции, не успешное восстановление/переименование.** Файлы, службы и данные при этом не изменялись; реестр и вспомогательные операции явно подменены тестом.

В install_menu модель создания перехвачена: разные major допускаются (rc=0), та же пара отклоняется (rc=1), создание для занятой пары не вызывается. Этот результат соответствует новому критерию, но не доказывает весь положительный live cross-major сценарий.

Воспроизведение:
```bash
bash tmp/save/name-pair-regression.sh /mnt/d/Ai/pg_claster_creator NEW_LOG_DIR
```

## Особенности окружения и обвязки

- Лишние кавычки LANG на Mint не считаются дефектом. Основные сценарные фазы прошли. Дополнительный helper вызвал pg_createcluster напрямую и получил отказ до создания из-за LANG. Повтор выполнялся с LANG=ru_RU.UTF-8 и LC_ALL=C.UTF-8 только для дочернего процесса; системные настройки не изменены.

- Astra 1.8.6: подготовительные удаления выполнялись через ранее проверенный offline-обход известных service hooks. Во всех трёх транзакциях подтверждены тот же PID1, сохранность остальных пакетов и конфига, пустой dpkg audit. Это не подтверждение исправления vendor/systemd/PARSEC. В начале установлен Postgres Pro 14, не Tantor BE18.
- Предупреждения WSL о root user-session/размере терминала сохранены как диагностика окружения; не подменяют проверку работы PostgreSQL.
