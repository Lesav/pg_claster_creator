# Регрессия переименования 2.4.1 — 2026-09-12

Итог: **PASS для описанного ниже объёма**, не полный passed-журнал S01–S10.
`TEST-2.4.0-journal-fail.md` сохранён без изменения результата. Его BLOCKED-варианты, включая чистое APT-окружение, этим прогоном не закрываются.

## Исправления

- F1: native `pg_renamecluster` уже меняет конфигурацию; последующая буквальная подстановка повторно добавляла суффикс. Новая функция заменяет только полные старые пути/идентификаторы за один проход и не меняет уже обновлённые значения. Общая замена в restore/move-data не изменена.
- F2: из rename исключены enable/disable, переносится точный набор persistent/runtime Wants/Requires. `PG_CLUSTER_CONF_ROOT=/etc/postgresql` задан только дочернему native helper: проверено наличие соответствующего условия отключения reload во всех семи установленных реализациях. После подготовки unit выполняется один bounded reload. Прежний SEGV не повторился; это подтверждает работоспособность обхода на матрице, но не устанавливает внутреннюю причину дефекта systemd/PARSEC.
- Дополнительно: native helper переносит стандартный лог, но может оставить `config/log` на прежнее имя. Новый запуск вновь создавал старый лог и блокировал обратное переименование. Теперь обновляется только ссылка на точный стандартный лог; произвольные внешние log-пути не переназначаются.
- Перед rename подтверждается `pg_ctl status=3`; перед запуском PostgreSQL разбирает эффективную конфигурацию для data/HBA/ident. При ошибке сохраняются этап, код, старые/новые пути, конфигурация и unit; автоматического отката нет.

Поиск ошибок за окно 18:10–18:11 не показал прежнего SEGV менеджера systemd. На Astra 1.8.4/1.8.6 найдены предупреждения systemd-resolved о втором LLMNR responder; это не запись падения PID 1 и не результат проверки DNS.

Итого: **28 rename + 14 delete, все rc=0**. Логи: `tmp/rename-2.4.1-final/<WSL>/live.log`, before.log, after.log. Защищённые baseline/recovery-файлы оставлены в `/var/tmp/pgcc-delete-live.*` и `/var/tmp/pgcc-rename.*` соответствующих WSL; данные QA удалены. Общие /DATA, /.postgres и чужие файлы не удалялись. Предупреждения WSL о root user session встречались, но не прерывали проверяемые операции.
